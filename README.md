# basen-kalendarz

Расписание бассейна AGH (картинка на <https://basen.agh.edu.pl/plywalnia/rezerwacje>)
→ календарь свободных дорожек (`.ics`) на GitHub Pages для подписки в Proton Calendar
(или любом другом календаре, который умеет подписку по URL).

Непрерывные свободные отрезки считаются по каждой дорожке (занятые ячейки картинки — пропуски
между ними, рабочий день 6:00–22:20); отрезки разных дорожек с одинаковыми днём, началом и концом
объединяются в одно событие (`Sportowy · свободны дорожки 3–6`). События помечены как «свободное
время» (`TRANSP:TRANSPARENT`), поэтому не делают вас занятым в календаре.
Названия занятий не переносятся. События обычные, не повторяющиеся: по одному на каждую дату.

## Еженедельный пайплайн

`.github/workflows/update.yml` запускается по понедельникам (05:00 и 15:00 UTC) и вручную:

1. скачивает страницу, берёт даты из заголовка `Rezerwacje pływalni w dniach 19-25.10.26 r.`
   и самый крупный вариант картинки;
2. распознаёт сетку и занятость (если картинка не совпала с ожидаемой вёрсткой — запуск падает,
   GitHub присылает письмо, опубликованный календарь остаётся прежним);
3. сохраняет неделю в `data/weeks/<начало>.json` и коммитит её — календарь собирается из всех
   сохранённых недель, поэтому прошлые недели не пропадают из подписки;
4. публикует на GitHub Pages `sportowy.ics`, `index.html` и превью распознавания `podglad.webp`.

Картинка и превью каждого запуска лежат 90 дней в артефактах запуска (Actions → запуск → `work`).

### Настройка на GitHub (один раз)

1. Создать **публичный** репозиторий (Pages на бесплатном тарифе работает только с публичными)
   и запушить в него этот проект.
2. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
3. Actions → «Обновление календаря» → **Run workflow**, дождаться зелёного запуска.
4. Календарь появится по адресу `https://<user>.github.io/<repo>/sportowy.ics`.

### Подписка в Proton Calendar

Proton Calendar → «+» рядом с календарями → **Add calendar from URL** → вставить адрес `.ics`.
Proton сам периодически перечитывает подписку, обновления появятся не мгновенно.

## Локальный запуск

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# весь пайплайн с живой страницей (результат в site/ и work/, неделя — в data/weeks/)
.venv/bin/python -m basen_kalendarz.update

# только распознать конкретную картинку
.venv/bin/python -m basen_kalendarz tests/fixtures/grafik.webp --od 2026-10-19 --do 2026-10-25
```

Параметры распознавания картинки:

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `--basen` | `sportowy` | `sportowy`, `szkoleniowy` или `rekreacyjny` |
| `--od` / `--do` | сегодня / неделя от `--od` | период (включительно); на каждую дату создаются свои события |
| `--out` | `out/` | папка для `kalendarz.ics`, `events.json`, `podglad.png` |

## Как это работает

- `fetch.py` — страница → даты недели и картинка (самый крупный вариант из `<picture>`).
- `grid.py` — сетка: разделители дней, 15-минутные колонки (первая — 6:00), 15 строк дорожек в дне.
- `occupancy.py` — медианный цвет внутри каждой ячейки; всё, что не белое, означает «занято».
- `events.py` — свободные отрезки по дорожкам (инверсия занятости) и их объединение по одинаковому времени.
- `export.py` / `weeks.py` — ICS (Europe/Warsaw) и архив недель; UID события зависит от даты,
  дорожек и времени, поэтому повторные запуски не создают дубликатов.
- `update.py` — пайплайн целиком.

## Тесты

```sh
.venv/bin/python -m pytest -q
```

Распознавание проверяется на `tests/fixtures/grafik.webp` (сверено вручную по превью),
разбор страницы — на сохранённой копии `tests/fixtures/rezerwacje.html`. Сеть тестам не нужна.
